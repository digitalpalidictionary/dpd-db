## Executor rules

- Phases 1–4 run on the laptop by the implementing agent. Phases 5–6 change the live server and are run by the **server agent** through the `/herdr-remote` skill (how to reach it: `kamma/archive/20261102_contrib_mem_wordfinder_lazy/handoff.md`, "The server agent"), or by the **owner**. The laptop agent never ssh-es to the server on its own; it sends the server agent one step at a time and reads the result back.
- Never run git commands. The owner commits. Never write to GitHub.
- Never run `git stash`, `git checkout -- <path>`, `git restore` or `git reset --hard` (shared working tree).
- Probes and throwaway apps go in the session scratchpad, never in the repo or the home folder.
- After editing any Python file, run in order: `uv run ruff check --fix <file>`, `uv run ruff format <file>`, pyright (`uv run pyright <file>` for `tools/` and `scripts/`; `uv run pyright --project /dev/null <file>` for `gui2/` and `tests/`), then the related tests. Fix pre-existing errors in touched files too.
- Any command that may take over 60 s runs in the background with a pid file and a bounded wait: `timeout 600 bash -c 'until <check>; do sleep 5; done'`.
- No server address or home path in any committed file: write `<server-ip>`, `<repo root>`.
- Allowed commands on the laptop: `uv run …` (ruff, pyright, pytest, gui2 in web mode, the probe app), `just typecheck`, `playwright-cli …` (headless, except `attach --extension=chrome` in 5.4), `curl`, `ps`, `kill <pid>`, `ss -ltnp`, and read-only `rg`, `grep`, `ls`, `cat`, `tail`. No git.
- Allowed commands on the server, through the server agent only: `git pull --ff-only origin main` and `git log -1 --format=%h` in the server clone (the "no git" rule is for the laptop agent; the server pull is how code reaches the server), `uv run --no-sync scripts/server_contrib/maintenance_window.py …` (5.7 only), `systemctl`, `journalctl`, `nginx -t`, `crontab -l`, `crontab <file>`, `install`, `cp`, `sed -i` on the files named in the tasks, `cat /proc/<pid>/status`, and read-only `grep`, `ls`, `cat`, `tail`. Long runs use a pid file and `timeout … bash -c 'until …'` waits.

## Architecture Decisions

- **Process exit, not in-process freeing.** CPython rarely returns freed memory to the OS; ending the process is the only dependable way to get the ~1 GB back. systemd `Restart=always` brings back an empty ~87 MB process. No on-demand start (spec "What's not included").
- **Activity from Flet's two inbound paths.** Wrap `Session.dispatch_event` and `Session.apply_patch` per page. This ties gui2 to Flet internals; a guard test and a startup log line are the alarm.
- **One new gui2 module, `gui2/server_lifecycle.py`,** holds idle sleep and the banner: constants, pure decision functions (unit-tested without Flet), and one `Lifecycle` object with a daemon thread. `gui2/main.py` only calls `attach(page)` and two log lines. Nothing else in gui2 learns about it, apart from the banner exclusion in `gui2/ui_utils.py`.
- **One shared module, `tools/contrib_notice.py`,** owns the notice file format and path for both the window (writer) and gui2 (reader), in `tools/` because both sides import it and `scripts/` must not import `gui2/`.
- **The window arms its own warning** (`--warn-minutes`), so no second cron job or wrapper can stop instances without warning. The wait is an injectable `WindowSteps` field with a default, so the existing tests' explicit `WindowSteps(...)` calls keep working.
- **Static pages served by nginx,** one site-level regex location for both pages, plus one per-user `error_page` line (needed because the per-user block already sets its own `error_page`).
- **Not abstracted:** no generic "message system", no ad-hoc announcement command, no config file for the step list. The step list and timings are module constants; only the idle minutes has an env override (the kill switch).
