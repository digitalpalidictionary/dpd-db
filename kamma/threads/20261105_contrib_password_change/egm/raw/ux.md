Read: brief, `add_contributor.sh`, runbook, all three nginx templates, `pyproject.toml`, `gui2/main.py`, `gui2/contributor_tabs.py`. Line numbers were not returned by my reads, so I anchor to symbols/sections.

**Blocker — a contributor has no way to learn the page exists.** Discovery is deferred (brief fork 4) and nothing else supplies it: the contributor surface in `gui2/contributor_tabs.py` carries only `READ_ONLY_MESSAGE`, no help/link, and `NEW_SERVER_RUNBOOK.md` §12e hands over the address with no mention of passwords. A non-technical volunteer will never guess `https://DOMAIN/password/`. Fix: one menu/help button in gui2, plus the URL in the §12e handout — or serve it at `/<user>/password/` so trimming their own address is enough.

**Blocker — the rewritten hash file must keep mode 640 root:www-data.** `add_contributor.sh` does `chmod 640` + detection of nginx's group precisely because "every request to the new URL answers 500". A root FastAPI process doing tempfile + `os.replace` produces 644 root:root; nginx then answers 500 on every request while the change page reports success — the contributor is locked out of the editor. Fix: `fchmod(0o640)`, `chown` to the nginx gid before replace, stat-verify after, abort and restore on mismatch.

**Major — a password change does not end the live session.** Basic auth is checked at handshake only; `nginx_contrib_user.conf.template` holds the Flet websocket open with `proxy_read_timeout 3600s` and never re-authenticates. Whoever the password change was meant to lock out keeps editing for up to an hour. Fix: say so on the success page, and/or restart `dpd-gui@<user>` after the change (warn about unsaved work).

**Major — stale cached credential, no way to clear it.** Basic-auth creds cache per host+realm and cannot be cleared by a page. First reload of `/<user>/` resends the old password, `auth_basic "DPD contributor <user>"` answers 401, and the prompt arrives prefilled with the old one — Enter again → loop → "the change broke my account". Success copy must instruct: close every DPD tab, reopen, cancel any prefilled prompt. Also never hand out `https://user:pass@host/` URLs; they bake into history.

**Major — errors must distinguish wrong password from broken server.** `htpasswd -v` exits non-zero for a mismatch and for I/O/permission faults; treating any non-zero as "wrong password" makes a server fault look like the volunteer's typo. Branch on exit code, log stderr, and show "the server could not check your password — tell the maintainer". Also: `htpasswd -vb` puts the plaintext password in argv, visible in `ps` to every local user — the runbook's rule 1 forbids exactly that. Use `-i`/stdin.

**Major — no confirmation field, and no forgotten-password path.** `htpasswd` accepts any bytes; one typo in a single field locks the contributor out, and `add_contributor.sh` refuses an existing user, so the maintainer improvises `htpasswd -B` by hand — likely dropping the 640/www-data fix above. Fix: a second "type it again" field, a stated minimum length, and a `scripts/server_contrib/set_password.sh` with a runbook entry.

**Major — the shared path is an unauthenticated password oracle.** No `limit_req` or fail2ban exists in any template, and `htpasswd -B`'s default bcrypt cost is 5. Fix: `limit_req` on that path, `-C 12`, and prefer fork 1 (per-user path behind the realm that already authenticated).

**Nit — `password` is a legal username** under `add_contributor.sh`'s regex, and collides with a shared `/password/` location. Reserve it as `added` is reserved. Copy should also state that the username is the word in their address.
