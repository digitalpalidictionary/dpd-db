## Findings

**1. Blocker — `error_page 403 =302` will not redirect the browser** · spec §"Forced-first-change gate" (`error_page 403 =302 /@USER@_/password/;`). Two defects in one line: (a) the stray `_` yields `/alice_/password/`, which matches no location; (b) with a *relative* URI, `error_page` performs an **internal** redirect — nginx replays the URI and returns that body with status 302 and **no `Location` header**. Failure: the browser stays at `/alice/`, renders the password page there, every Flet asset/API call under `/alice/` is likewise internally swapped for HTML, and the form's relative POST target resolves against `/alice/`. Fix: `error_page 403 = @pw;` + `location @pw { return 302 /$user/password/; }` (or per-user `return 302 /alice/password/` in the rendered conf), and state in the spec that a real `Location` must be emitted, with the deploy CHECK asserting `curl -i` shows one.

**2. Blocker — a newly added contributor's editor answers 500** · `nginx_contrib.conf.template:13` includes only `/etc/nginx/dpd/*.conf`; that site file is deployed **by hand** and `server_setup.sh` explicitly leaves nginx out ("Left out on purpose: … nginx"). `add_contributor.sh` renders the user template (which will carry `auth_request /_dpd_pw_check`) unconditionally. If the live site file predates this thread, the subrequest 404s → non-2xx/401/403 → 500 for that user's whole URL. The runbook wording "add the internal location … **if** regenerating it" makes the fix conditional. Fix: `add_contributor.sh` greps the installed site file for `_dpd_pw_check` and refuses (or warns loudly, like the chgrp path); runbook step is unconditional and `nginx -t`-gated.

**3. Major — CSRF changes a password from any web page.** The form has no current-password field, no token, no Origin check; cached basic-auth credentials are attached to cross-origin form POSTs. Attack: a hostile page posts `new=x&repeat=x` to `https://host/alice/password/`. Fix: one-time token rendered in the GET form and consumed server-side, or an Origin/Referer allowlist — and weigh it in the spec, since the current-password field was dropped for oracle reasons that don't apply behind the realm.

**4. Major — "atomic replace is enough" is wrong** · spec §Constraints. Two concurrent POSTs both derive from the original; step 5 verifies the *shared path*, so the loser can read the winner's hash, pass, delete the marker, and show success for a password that is not on disk. Fix: verify the private temp before `os.replace`, under a per-user lock.

**5. Major — the step-5 fallback verifies nothing that matters.** "Hash line exists, starts with `$2y$`, stat checks pass" proves file shape, not the credential: htpasswd could have hashed an empty/truncated stdin. Outcome: user locked out with a plausible file, marker deleted, no signal. Fix: never delete the marker unless a real verify succeeded; keep `.bak` and escalate to the runbook otherwise.

**6. Major — `/check` fail-open is unspecified** · spec §`GET /check`. Missing/garbled `Authorization` behaviour is never stated; a 200 there disables the whole gate. Fix: 403 for unparsable identity + a test.

**7. Major — the service trusts any local caller.** `POST /` accepts any Authorization header sent to `127.0.0.1:8500`; any local process sets any user's password knowing nothing. "There is no unauthenticated endpoint" (What's not included) is false for the service. Fix: shared secret header injected by nginx, or a unix socket; otherwise record the accepted risk.

**8. Major — subrequest header hygiene.** `/_dpd_pw_check` inherits `Upgrade`/`Connection: upgrade` from the Flet handshake (`nginx_contrib_user.conf.template:11-12`) and gets no `X-Real-IP`; no connect/read timeout is specified, so a hung service stalls every editor request. Fix: strip `Upgrade`/`Connection`, add `proxy_connect_timeout 1s` (and read timeout).

**9. Major — `error_page 403` swallows the app's own 403s** inside `location /@USER@/`, redirecting mid-session requests to the password page. Specify and test, or gate on a distinct status.

**10. Nit** — `add_contributor.sh`: marker written last under `set -e`; a failure leaves an unforced user and a rerun refused (`already exists`). **11. Nit** — no max password length (bcrypt's 72-byte truncation), no `.bak` rotation, temp cleanup on failure unspecified, mid-request marker race documented nowhere. **12. Nit** — tests: gid preservation needs `chown` (root-only), so the test is likely silently skipped; missing cases for absent Authorization, unarmed-marker POST, nonexistent htpasswd, and `MemoryMax=128M` accepting an OOM-kill loop as "fail-closed".
